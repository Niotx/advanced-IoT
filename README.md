# Advanced IoT — Engineering Through Real Problems

این ریپازیتوری، **راهنمای عملی دوره اینترنت اشیای پیشرفته** است. در طول دوره، یک سیستم پایش دما و رطوبت را قدم‌به‌قدم توسعه می‌دهیم و هر فناوری را زمانی بررسی می‌کنیم که برای حل یک مسئله به آن نیاز داریم.

> **روش استفاده:** اسلایدها مسئله و تصمیم مهندسی را توضیح می‌دهند؛ ویدئوهای عملی اجرای مراحل را نشان می‌دهند؛ این README مسیر کار را مشخص می‌کند؛ و هر پوشه، کد و توضیحات مستقل همان مثال را در اختیار شما می‌گذارد.

## ۱. اولین نمونه: اندازه‌گیری و نمایش محلی

**مسئله:** اندازه‌گیری دما و رطوبت محیط، بدون نیاز به شبکه.

**سخت‌افزار:** ESP32 DevKit V1، سنسور DHT22 و نمایشگر OLED SSD1306 با ارتباط I2C.

**مراحل:**

1. مطابق جدول اتصالات و تصویر سیم‌کشی، قطعات را وصل کنید.
2. کتابخانه‌های موردنیاز را در Arduino IDE نصب کنید.
3. فایل `ESP32_DHT22_OLED.ino` را باز و روی ESP32 بارگذاری کنید.
4. خروجی OLED و Serial Monitor را بررسی کنید.
5. خطای خواندن سنسور را نیز آزمایش کنید.

**کد، اتصالات و راهنمای اجرا:** [ESP32_DHT22_OLED](./ESP32_DHT22_OLED/README.md)

**خروجی مورد انتظار:** مقادیر دما و رطوبت به‌صورت محلی نمایش داده می‌شوند؛ در صورت نامعتبر بودن خواندن سنسور، پیام خطا ظاهر می‌شود.

## ۲. مسئله ارتباط از راه دور

**نیاز جدید:** کاربر باید بتواند داده‌های سنسور را از دستگاه دیگری دریافت کند.

برای انتخاب فناوری ارتباط، الگوهای **Request/Response** و **Publish/Subscribe** و گزینه‌های HTTP/HTTPS، MQTT و CoAP را مقایسه می‌کنیم.

**تصمیم معماری این پروژه:** برای تله‌متری دوره‌ای، MQTT را با یک Broker محلی روی Raspberry Pi انتخاب می‌کنیم. این انتخاب مختص نیازهای پروژه است؛ HTTP/HTTPS و CoAP در سناریوهای دیگر همچنان می‌توانند مناسب باشند.

> تا این مرحله، اتصال MQTT هنوز در کد نمونه اولیه پیاده‌سازی نشده است.

## ۳. آماده‌سازی Raspberry Pi و دسترسی از راه دور

**مسئله:** برای اجرای سرویس‌های سمت شبکه، ابتدا به یک Raspberry Pi آماده و قابل مدیریت نیاز داریم.

**سخت‌افزار:** Raspberry Pi 4 Model B (4GB RAM)، منبع تغذیه مناسب، کارت microSD و اتصال شبکه.

### اجرای سریع

1. [Raspberry Pi Imager](https://www.raspberrypi.com/software/) را روی مک نصب کنید.
2. سیستم‌عامل **Raspberry Pi OS Lite (64-bit)** را برای Raspberry Pi 4 انتخاب کنید.
3. در بخش تنظیمات اولیه Imager، نام میزبان، حساب کاربری، Wi-Fi و **SSH** را پیکربندی کنید.
4. کارت را در Raspberry Pi قرار دهید و دستگاه را روشن کنید.
5. در ترمینال مک، با نام کاربری و میزبان **واقعیِ تنظیم‌شده توسط خودتان** وصل شوید:

```bash
ssh iotuser@iot-pi.local
```

در این مثال `iotuser` و `iot-pi` صرفاً نام‌های نمونه هستند. اگر `*.local` در شبکه شناسایی نشد، IP دستگاه را از فهرست دستگاه‌های متصل در روتر پیدا کنید.

بعد از اتصال، IP فعلی را مشاهده کنید:

```bash
hostname -I
```

در ادامه، متناسب با شبکه خودتان، آدرس پایدار (**DHCP Reservation** یا **Static IP**) را تنظیم کنید. ورود با **SSH Key** را آزمایش کنید و سپس دسترسی SSH را سخت‌سازی کنید: غیرفعال‌کردن ورود مستقیم **root**، غیرفعال‌کردن احراز هویت با رمز پس از تأیید کلید، تغییر اختیاری پورت SSH و نصب **UFW** برای محدودکردن پورت‌های ورودی. **قبل از فعال‌کردن UFW یا تغییر پورت، دسترسی SSH جدید را مجاز کنید تا اتصال قطع نشود.**

تمام دستورها، نکات بازیابی دسترسی و آزمون‌های این بخش در راهنمای مستقل زیر قرار دارند.

**راهنمای کامل، دستورات، آزمون‌ها و رفع خطا:** [RaspberryPi_SSH_SETUP](./RaspberryPi_SSH_SETUP/README.md)

**خروجی مورد انتظار:** اتصال قابل تکرار از مک به Raspberry Pi در شبکه محلی، ترجیحاً با SSH Key.

## ۴. راه‌اندازی MQTT Broker روی Raspberry Pi

**مسئله:** برای دریافت داده‌های ESP32 به یک Broker محلی نیاز داریم.

1. بسته‌های `mosquitto` و `mosquitto-clients` را نصب کنید و وضعیت سرویس را بررسی کنید.
2. با `mosquitto_sub` و `mosquitto_pub` تبادل پیام را روی خود Raspberry Pi آزمایش کنید.
3. یک کاربر MQTT ایجاد کنید و Listener شبکه محلی را با `allow_anonymous false` تنظیم کنید.
4. دسترسی TCP/1883 را در UFW **فقط برای شبکه مورداعتماد** مجاز کنید.
5. تبادل پیام از دستگاه دیگری در شبکه را با حساب مجاز تست کنید.

**تمام دستورها، خروجی مورد انتظار و رفع خطاها:** [RaspberryPi_MQTT_BROKER](./RaspberryPi_MQTT_BROKER/README.md)

**خروجی مورد انتظار:** Mosquitto روی Raspberry Pi فعال است و کلاینت‌های مجاز شبکه محلی می‌توانند پیام MQTT ارسال و دریافت کنند.

## ۵. ارسال داده DHT22 از ESP32 با MQTT

**مسئله:** داده‌های سنسور علاوه بر OLED، باید از ESP32 به Broker روی Raspberry Pi ارسال شوند.

1. طبق [راهنمای Broker](./RaspberryPi_MQTT_BROKER/README.md)، از فعال‌بودن سرویس و دسترسی حساب MQTT مطمئن شوید.
2. در [ESP32_MQTT_PUBLISH](./ESP32_MQTT_PUBLISH/README.md) کتابخانه‌ها را نصب کنید و از `secrets.h.example` یک فایل محلی `secrets.h` بسازید.
3. IP واقعی Raspberry Pi و اطلاعات Wi-Fi/MQTT را فقط در `secrets.h` وارد کنید؛ آن را در GitHub منتشر نکنید.
4. فایل `ESP32_MQTT_PUBLISH.ino` را با Arduino IDE روی ESP32 بارگذاری کنید.
5. در MQTT Explorer یا `mosquitto_sub`، پیام‌های `iot/room-01/telemetry` و `iot/room-01/status` را ببینید.

**کد کامل، دستورهای قابل کپی، خروجی مورد انتظار و رفع خطا:** [ESP32_MQTT_PUBLISH](./ESP32_MQTT_PUBLISH/README.md)

**نتیجه:** نمایش OLED محلی باقی می‌ماند و اندازه‌گیری‌های معتبر از طریق MQTT در شبکه آزمایشگاهی ارسال می‌شوند. در این نسخه هنوز زمان واقعی NTP، ذخیره داده در قطعی شبکه و TLS پیاده‌سازی نشده‌اند.

## ۶. دریافت و پردازش تله‌متری با Python

**مسئله:** پس از Publish موفق ESP32، داده باید روی Raspberry Pi در یک برنامه قابل پردازش دریافت شود.

1. مطابق [راهنمای Broker](./RaspberryPi_MQTT_BROKER/README.md)، از فعال‌بودن سرویس Mosquitto مطمئن شوید.
2. با [`ESP32_MQTT_PUBLISH`](./ESP32_MQTT_PUBLISH/README.md) داده‌های دما و رطوبت را Publish کنید.
3. در [`RaspberryPi_MQTT_SUBSCRIBER`](./RaspberryPi_MQTT_SUBSCRIBER/README.md)، محیط Python و کتابخانه `paho-mqtt` را آماده کنید.
4. اسکریپت `subscriber.py` را با حساب MQTT اجرا کنید و پیام‌های `telemetry` و `status` را مشاهده کنید.
5. داده دریافت‌شده را با خروجی OLED و Serial Monitor مقایسه کنید؛ پیام وضعیت `offline` را هم در سناریوی قطع ESP32 آزمایش کنید.

**کد، دستورات قابل کپی، خروجی نمونه و رفع خطا:** [RaspberryPi_MQTT_SUBSCRIBER](./RaspberryPi_MQTT_SUBSCRIBER/README.md)

**خروجی مورد انتظار:** پیام JSON به مقادیر دما، رطوبت، شناسه دستگاه و `uptime_ms` تبدیل می‌شود. این مرحله **ذخیره‌سازی، داشبورد یا Timestamp واقعی** اضافه نمی‌کند؛ آن‌ها در مراحل بعد بررسی می‌شوند.
